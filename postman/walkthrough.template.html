The whole flow, request by request

Every public API call in the order that tests the application end to end: register, publish a job, upload a resume, apply, get scored, get hired, then the admin tools. The flows behind each step are explained in the architecture doc.

Generated from postman/SmartHire.postman_collection.json by make api-walkthrough. Verified end to end with newman: 44 requests, 0 failures.

Before you start

  1. make up, then wait until make ps shows the services healthy.
  2. Create an admin whose password matches the password variable (ChangeMe123!):
    docker compose exec -it identity python -m app.cli create-admin admin@example.com
  3. Import the collection into Postman and use Run collection on folders 1-9 with a delay of about 2500 ms (publishing, parsing and scoring run in the background).
  4. Running it again? Change candidateEmail and recruiterEmail (an email registers only once: 409).

How to read the steps

  • Paths are relative to the gateway, http://localhost:8000. {{values}} are collection variables, saved by earlier steps ("Saves").
  • The coloured tag is the token to send as Authorization: Bearer …. Refresh and logout use the refresh_token cookie set by login (Postman keeps it; with curl use -c jar -b jar).
  • Every error has the shape {"error": {"code", "message", "request_id", "details?"}}.
  • Watch the background work in Temporal UI :8088, Mailpit :8025, Jaeger :16686, Grafana :3001.
